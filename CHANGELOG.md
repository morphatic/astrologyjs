# Change Log

## [v1.3.2](https://github.com/morphatic/astrologyjs/tree/v1.3.2) (2026-08-15)

**astrologyjs 1.x is retired. Use [astrologyjs 2.x](https://www.npmjs.com/package/astrologyjs).**

This release repairs nothing. It replaces a failure that explained nothing with one that explains
itself, and that is its entire content.

1.x read planetary positions from a free ephemeris service at `morphemeris.com/ephemeris.php` that
went offline years ago. Since then every chart request has received an HTML error page instead of
JSON, surfacing as `SyntaxError: Unexpected token < in JSON at position 0` several frames from the
cause. Four issues going back to 2017 report it.

- Every entry point now throws an error naming the dead backend, the replacement, and how to install
  it. The text is exported as `RETIREMENT_NOTICE`; the error carries `code:
  'ASTROLOGYJS_1X_RETIRED'`.
- The error also records that 1.x results were unreliable independently of the outage: `Aspect.orb`
  reported the fractional part of the separation rather than the distance from exactness, so a trine
  at 118.5° reported an orb of 0.5 instead of 1.5.
- The 1.3.1 public surface is preserved exactly — same names, signatures, `ChartType` values, and
  the same three bundles under the same three filenames — so upgrading from 1.3.1 still compiles and
  still resolves before it explains itself.
- Both runtime dependencies are dropped (`node@0.0.0` and `babel-runtime`). A package that computes
  nothing installs nothing.
- Published under the `legacy` dist-tag, so `latest` continues to point at 2.x.

Nothing on the `legacy/1.x` branch is shared with 2.x, which is a ground-up reimplementation on the
[Morphemeris](https://api.morphemeris.com) API.
